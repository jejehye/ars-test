# ARS 메뉴 테스트

`ARS변경내역_최종_0904.xlsx` 의 **27년최종ARS메뉴** 시트에서 테스트 케이스를 뽑아,
개발용 ARS로 실제 전화를 걸며 메뉴 트리를 검증하는 Android/iOS 앱.

- 케이스 **101건** (대메뉴 10개, depth 1~3), 결번 케이스 37건
- 원본 xlsx는 **읽기 전용**. 추출 스크립트가 실행 전후로 SHA-256을 확인하고, 달라지면 빌드를 멈춘다.

## 실행

기본은 **웹(PWA)** 이다. 설치 없이 Android·iOS·데스크톱 브라우저에서 같은 주소로 열린다.

```bash
npm install
npm run serve      # 빌드 후 LAN 공개 (휴대폰에서 http://<맥 IP>:4173 접속)
npm run dev        # 개발 서버, LAN 공개
npm test           # 도메인 단위 테스트
npm run build      # 추출 + 타입체크 + 번들 → dist/ (정적 호스팅에 그대로 올리면 된다)
```

데스크톱 브라우저에서는 `tel:` 이 동작하지 않아 발신 버튼이 비활성화된다. 화면과 다이얼
문자열 확인까지만 가능하고, 실제 테스트는 휴대폰 브라우저에서 해야 한다.

### 홈 화면에 추가 (선택)

`manifest.webmanifest` + 서비스 워커가 들어 있어 홈 화면에 추가하면 전체 화면으로 뜨고
오프라인에서도 열린다. 단 **서비스 워커는 HTTPS 또는 localhost 에서만 등록**되므로,
LAN 의 `http://192.168.x.x:4173` 으로 열면 앱은 정상 동작하되 오프라인 캐시는 켜지지 않는다.

첫 실행 시 **설정 탭에서 발신 번호를 입력**해야 한다. 번호는 단말에만 저장되고 저장소에는 커밋되지 않는다.

### 네이티브 (선택 — Android 완전 자동이 필요할 때만)

웹만으로 충분하면 이 단계는 건너뛰어도 된다. 같은 코드베이스에서 Android 앱으로 감싸면
기본 전화앱 등록이 가능해지고 완전 자동·녹음·STT·배치 실행이 열린다.

```bash
npx cap add android
# native/README.md 를 따라 플러그인 소스를 복사·등록
npm run sync
```

## 동작 모드

| 플랫폼 | 발신 | DTMF | 녹음/STT |
|---|---|---|---|
| Android (기본 전화앱 등록) | 자동 | `playDtmfTone()` | 마이크 녹음 + VAD + 온디바이스 STT |
| Android (미등록) | 자동 | 쉼표 다이얼 | 불가 |
| iOS | 다이얼러 표시 → 사용자 탭 | 쉼표 다이얼 | 불가 |
| 웹 (휴대폰 브라우저) | `tel:` 링크 → 사용자 탭 | 쉼표 다이얼 | 불가 |
| 웹 (데스크톱) | 불가 | — | 불가 |

웹 모드에서는 Capacitor 가 OS를 전부 `web` 으로 보고하므로, 쉼표 1개의 길이는 UA 로
Android/iOS 를 구분해 적용한다 (`webOs()`).

화면은 `getCapabilities()` 결과에 따라 자동으로 완전 자동 / 반자동을 전환한다.

완전 자동 모드에서는 고정 대기 대신 **멘트가 끝나는 순간을 소리로 감지(VAD)** 해 DTMF를 보낸다.
감지에 실패하면 설정된 고정 대기로 되돌아간다. 녹음은 16kHz 모노 PCM으로 남기고,
Android 12+ 의 `SpeechRecognizer` 파일 입력으로 오프라인 전사해 기대 키워드와 대조한다.
전사가 비거나 일부만 맞으면 `FAIL`이 아니라 **`REVIEW`** 로 두어 사람이 확인하게 한다.

### 배치 실행

배치 탭에서 케이스 탭의 필터를 그대로 이어받아 순차 실행한다. 케이스 사이에 `cooldownMs` 만큼 쉬고,
**인증 실패가 두 번 감지되면 즉시 멈춘다** — 반복 오입력으로 계좌가 잠기면 이후 케이스가 전부 무의미해지기 때문이다.

## 자격증명 취급

계좌번호는 세션마다 입력받고, 비밀번호는 설정의 더미 기본값(`0000`)을 쓴다.

| | DUMMY | SECURE |
|---|---|---|
| 조건 | 기본값 그대로 + `env: test` + 허용 번호 | 비밀번호를 직접 입력했거나 운영 환경 |
| 화면·로그 | 평문 | 마스킹 |
| 녹음 | 유지 | 비밀번호 구간 일시정지 |
| CSV | 포함 | 제외 |
| 쉼표 다이얼 | 허용 | **차단** (`SecretInDialStringError`) |

쉼표 다이얼은 입력값이 통화 기록에 평문으로 남는다. 그래서 실제 비밀번호는 절대 싣지 않고,
Android 완전 자동 모드의 `playDtmfTone()` 으로만 보낸다.

## 안전장치

- 발신 번호 화이트리스트 — 허용 목록에 없으면 발신 자체를 차단
- 상담원 연결 23건 / 주문·이체 27건은 목록에서 **기본 제외**, 포함 시 경고 표시
- 운영 환경으로 설정이 바뀌면 더미 비밀번호 사용을 거부하고 SECURE로 강등
- 주문·이체 케이스는 최종 안내를 4초만 듣고 통화를 끊어 확정 단계로 들어가지 않는다
- 배치 실행 중 인증 실패 2회 감지 시 자동 중단

## 아직 확정되지 않은 값

아래는 전부 **추정치**다. Phase 0 실측 전까지 타이밍이 어긋날 수 있고, 화면 상단에
`대기시간 미검증` 배지가 표시된다. 측정 절차는 `docs/phase0-checklist.md` 참고.

| 값 | 현재 | 근거 |
|---|---|---|
| 쉼표 1개 지속시간 | 2000ms (양 플랫폼) | 업계 통용값. Android는 3000ms일 가능성 있음 |
| 초기 대기 | 8000ms | 추정 |
| 단계간 대기 | 4000ms | 추정 |
| 인증 필요 메뉴 | 대메뉴 2·3·4·5 (42건) | 시트에 인증 정보가 없어 추정 |
| 계좌번호 자릿수 / `#` 종단 | 11자리 / 필요 | 추정 |
| `expectedKeywords` | 메뉴명에서 자동 생성 | 1회차 실행 후 실제 멘트로 보정 필요 |
| VAD 음성 판정 기준 | RMS 600 | 실기기 음량에 맞춰 `PromptDetector.SPEECH_RMS` 조정 필요 |
