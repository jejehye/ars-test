# Phase 0 실측 체크리스트

코드로는 확인할 수 없고 실제 통화로만 확정되는 값들이다.
결과를 앱 **설정 탭**에 입력하고 "실측 완료"를 켜면 미검증 배지가 사라진다.

## 준비

- [ ] 전용 Android 테스트 단말 (기종·OS 버전 기록)
- [ ] 앱 설치 후 기본 전화앱으로 지정
- [ ] 발신 번호를 설정 탭에 입력
- [ ] 테스트 계좌번호 확보 (잔고 없는 개발계좌)

## 1. 통화 중 마이크 녹음 가능 여부 — **최우선**

가장 큰 리스크. 막히면 STT 자동 판정 설계(Phase 5)를 폐기해야 한다.

- [ ] 통화 연결 → 스피커폰 → `startRecording()` 호출이 예외 없이 통과하는가
- [ ] 저장된 m4a에 ARS 안내가 **알아들을 수 있게** 녹음되는가
- [ ] 결과: 가능 / 불가 / 무음 파일만 생성

## 2. 쉼표 1개의 실제 지속시간

플랫폼별로 다를 수 있다. 앱의 다이얼 문자열 계산이 이 값에 직접 걸려 있다.

- [ ] Android: `tel:<번호>,,,,1` 로 발신 → 연결 시점과 DTMF 톤 시점 간격 측정
- [ ] iOS: 동일 측정
- [ ] 결과: Android ___ ms / iOS ___ ms

## 3. barge-in 지원 여부

지원하면 대기시간을 2~3초로 줄일 수 있어 101케이스 총 실행시간이 절반 이하가 된다.

- [ ] 멘트 재생 중 1초 시점에 DTMF 전송 → 정상 진입하는가
- [ ] 결과: 지원 / 미지원

## 4. 멘트 길이와 무입력 타임아웃

- [ ] 대메뉴 안내(0~9 나열) 길이 ___ 초
- [ ] 주요 중메뉴 안내 길이 ___ 초
- [ ] 입력 없이 대기 시 재안내/종료까지 ___ 초 → 대기시간 상한

## 5. 인증 프롬프트

시트에 없는 정보라 전부 실측으로 채워야 한다.

- [ ] 어느 메뉴에서 계좌번호를 요구하는가 (현재 대메뉴 2·3·4·5로 추정)
- [ ] 계좌번호 자릿수 ___ / `#` 종단 필요 여부
- [ ] 비밀번호 자릿수 ___ / 기본값 `0000` 으로 인증이 통과하는가
- [ ] 이체비밀번호가 대메뉴 4에서 별도로 필요한가
- [ ] ARS가 입력값을 음성으로 복창하는가 (복창하면 해당 구간 녹음 제외 필요)

## 6. 대메뉴 3·4 안전 지점

- [ ] 주문·이체가 실제로 체결되기 직전 단계가 어디인가 → `stopBefore` 적용 지점 확정
